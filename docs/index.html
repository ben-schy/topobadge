GPX → multicolor 3D print

Turn a hike into a hex tile you can print.

Upload a GPX track. topobadge pulls real elevation and land-cover data, builds a small hexagonal relief map of the hike and its surroundings, and hands you a ready-to-print 3MF — grey rock, blue water, green forest, and white ice inlaid flush into the terrain, with the trail itself the only thing raised above the surface.

The palette

Five materials, one map

Every part of the terrain is sorted into a source class - trees, shrub, grassland, water, ice, roads, named landmarks, and more - and you decide which output layer each one prints as: merge grassland into rock, send ice to the water color instead of its own, or give roads their own layer entirely. Nothing here is hardcoded; see Layers & sources.

Base rock — #808080 Water — #2E75B6 Vegetation — #3C8C3C Ice / glacier — #FFFFFF Trail — #8B5A2B
Get running

Quick start

Everything runs locally — your GPX file and the generated models never leave your machine except to fetch public elevation/map data.

Install Python 3.11+

If you don't already have it: python.org.

Download the project and run run.bat

First run sets up a virtual environment and installs dependencies automatically; every run after that just starts the app.

Your browser opens to the local web UI

Drag in a .gpx file, pick a size, click Build.

Download combined.3mf and print

Or grab the individual .stl files for manual multi-material assignment in your slicer.

Prefer the command line?

pip install -e .
topobadge build my_hike.gpx
topobadge serve   # same thing, but as a local web page
Under the hood

How it works

Five stages, all running on your machine:

1 · Track & frame

Parse the GPX, pick a local UTM projection, and frame a hexagonal (or rectangular) working area around the track plus a buffer of surrounding context.

2 · Elevation

Fetch a real elevation grid for that area from USGS 3DEP, pre-resampled server-side to exactly the mesh resolution needed.

3 · Land cover & overlays

Fetch lake/stream/river features (USGS NHD, falling back to Esri Living Atlas), a vegetation/ice classification (NLCD), roads and other trails (USGS Transportation), and named landmarks (USGS GNIS) - each its own independent source class.

4 · Compose

Group every source class into whichever output layer you assigned it to, smooth the resulting boundaries, and build a solid grey terrain base notched wherever a layer sits so flush layers inlay into the surface instead of stacking on top of it; each layer's own rise (0 by default, positive for the trail) is what reads as physically raised.

5 · Export

Write each colored part as its own STL, bundle them into one colored 3MF, and render a top-down preview image.

The mesh step is the fiddly part. Each colored region is built directly from the same elevation grid as the base terrain (no boolean/CSG operations), included at whole-grid-cell granularity so diagonal-only touching regions can't produce a non-manifold, unprintable seam. Water, forest, and ice sit in a shallow pocket notched into the base so their tops land exactly at the surrounding terrain height — flush, not a bump. The trail uses the same pocket for a solid bond, but its top rises above the surrounding surface, so it's the one thing on the model you can actually feel.

The easy way

Web UI

Run topobadge serve (or double-click run.bat) and a page opens in your browser, in three steps. See Layers & sources for what the assignment table in step 2 actually controls.

Fetch

Drag in a GPX file, choose a size and shape, click Fetch Data. This is the only network-bound step (elevation, water, and land-cover data for the area) - typically 5-20 seconds.

Adjust & preview

Reassign any source class to any color layer, edit each layer's color and rise, tune widths and smoothing - the preview updates in well under a second per change, since nothing here touches the network again.

Generate

Click Generate 3D Files once it looks right, to build the actual meshes and get your STL/3MF/preview downloads.

Only the first step touches the network. Every data source topobadge uses is a government API (USGS 3DEP, NHD, Esri Living Atlas, and NLCD) rather than shared crowd infrastructure, so fetching is typically done in 5-20 seconds - and if a water source is briefly unreachable, topobadge automatically falls back to an independent one rather than failing the fetch - see Troubleshooting.
The core idea

Layers & sources

Every piece of geometry topobadge can draw - trees, shrub, grassland, water, ice, roads, other trails, named landmarks, and your own hike route - is a source class. Every source class is assigned to an output layer, and it's the layer that actually has a color and a height. Multiple source classes can share one layer (that's how trees + shrub + grassland all become one green vegetation layer by default), or you can split them apart, merge one into another, or hide any of them by assigning it to base.

Source classDefault layer
Trees, shrub, grassland, pasture/crops, wetlandVegetation (green)
Water (lakes, streams, rivers)Water (blue)
Ice / permanent snowIce (white)
Your hike routeTrail (brown, raised)
Roads, other trails, named landmarksBase (hidden) — opt in to show them

Two examples this was built around: reassign ice to the water layer (or to base, for plain rock) instead of giving it a separate color; reassign grassland to base while leaving trees on vegetation, so only actual forest reads as green.

Each layer also has its own color and rise — how far it sits above the surrounding surface. 0 means flush/inlaid (water and vegetation by default); positive means physically raised, like the trail. Any layer can be raised, not just the trail - a small default rise on the landmarks layer is what makes them tactile pins rather than flat markers. Region boundaries are also smoothed (rounding off blocky grid-cell corners) before meshing, tunable via the smoothing control.

In the web UI, this is the "Layer colors & heights" and "What maps to which layer" tables in step 2. From the CLI, use --vegetation-preset for the common case, or --layers-json for full control:

{
  "layers": {
    "roads": {"color_hex": "4A4A4A", "rise_mm": 0}
  },
  "layer_assignment": {
    "ice": "water",
    "grassland": "base",
    "roads": "roads",
    "landmarks": "trail"
  }
}

What you get

Output files

Written to <gpx name>_topo/ (or --out-dir) — only the parts actually present in the hike's area are written:

FileContents
base.stlThe grey terrain solid — always present.
water.stlLakes, ponds, streams, and rivers, where present.
vegetation.stlTrees/shrub/grassland/etc. assigned to the vegetation layer, where present.
ice.stlGlaciers/permanent snow, where present (and not merged elsewhere).
trail.stlThe hike route itself, raised above everything else.
roads.stl / other_trails.stl / landmarks.stlOnly written if you assign that source to a visible layer - hidden (merged into the base) by default.
combined.3mfAll present parts in one file, with color assigned per part.
preview.pngA top-down colored render for a quick sanity check.
A personal touch

Underside plaque

Optional text - a hike name, date, who was there - engraved flush into the underside in its own color, separate from the base rock. Set it in the web UI's "Underside text plaque" panel (step 2), or on the CLI:

topobadge build my_hike.gpx --mm-per-cell 0.35 \
  --plaque-text "James Peak\n9/15/26\nBen, Lillie, Brynn" \
  --plaque-width-mm 70

The text is mirrored automatically, the same convention used for a coin's reverse or a PCB's bottom silkscreen: the model is meant to be flipped over like a page (rotated about the vertical axis) to read it, so the source art is authored mirrored ahead of time.

Text needs a fine enough grid to resolve. The plaque is built on the same grid as everything else, so short strokes in small letters need enough grid cells to form at all. If a build logs a warning that the plaque didn't render, it tells you exactly which --mm-per-cell value (a step 1 / fetch-stage setting, so it needs a re-fetch) would fit it - as a rule of thumb, aim for roughly 8 grid cells per character across the longest line. Shorter text, a wider plaque, or a larger model all help too.
FlagDefaultWhat it controls

From file to filament

Printing it

For a single-material printer, base.stl alone already prints a clean relief tile. For multi-material printing (Bambu AMS, Prusa MMU, or similar):

Recommended: import the STLs together

Drag all the .stl files into your slicer at once — they share one coordinate origin, so they'll land in the right place automatically. Assign a filament color to each object in the part list.

Convenience: open combined.3mf

One file, colors already assigned. Works well in most slicers, but per-object color import in Bambu Studio specifically has had version-dependent bugs — if colors don't come through right, fall back to the STL method above.

Where the data comes from

Named landmarks (summits, passes, valleys, ...)USGS GNIS gazetteer (The National Map), no API keyUnited States only

Every data source is a US government/public API, so topobadge currently only produces full-color terrain for US hikes. An earlier version used OpenStreetMap for global reach, but its public Overpass API proved too unreliable in practice; USGS's suite of APIs (plus an independent Esri fallback specifically for water) has been consistently fast and available instead. Water is deliberately layered across three independent sources - both toggleable in the web UI's adjust step, or via --use-vector-water/--use-nlcd-water on the CLI - so a single outage doesn't take water off the map.

When something's off

Troubleshooting

Fetch finished, but there's no water/forest color

USGS's APIs have been reliable in practice, but they're still network services topobadge doesn't control. Water is layered across three independent sources (NHD, then Esri Living Atlas, then NLCD's own water class blended in) so a single outage rarely removes water entirely - but if NLCD itself is down, vegetation/ice/water-blend all go with it. topobadge continues with whatever it has rather than failing the fetch, and prints a warning to that effect. Re-fetching later fills things back in with no other changes needed; in the meantime, the adjust step's water-source toggles let you see exactly what's available and work around a partial outage rather than guessing.

Colors look wrong in my slicer

See Printing it — import the individual STL files together and assign filament colors by hand rather than relying on the combined 3MF's embedded color.

No terrain shows up at all / elevation looks flat Confirm the hike is within the United States — the elevation data source (USGS 3DEP) doesn't cover other countries yet.
